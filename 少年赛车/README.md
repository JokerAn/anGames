# 少年赛车

面向手机浏览器的 3D 赛道竞速。默认以走线、刹车点与实际冲线时间争夺名次；也保留可选的经典道具竞速。三条闭环赛道、三种车型与引擎、六车同场，支持同一局域网的双人比赛。

## 启动与手机游玩

使用 Node.js 20 或以上版本：

```sh
cd 少年赛车
npm install
npm start
```

macOS 可以双击 `启动游戏.command`。默认端口为 **3210**，服务会打印电脑和局域网地址。手机和电脑连接同一 Wi-Fi，手机打开终端提供的电脑 IP 地址，例如 `http://192.168.1.57:3210`。手机上的 `localhost` 指向手机自身。

推荐横屏，竖屏也支持完整操作，车库可上下滚动。车辆、纹理、环境、声音均由本地代码生成，游玩无需外部 CDN 或图片服务。更改端口使用 `PORT=3211 npm start`；ES modules 与联机服务要求通过 HTTP 打开。

双人选择「双人联机」，输入各自昵称及相同的 4–8 位数字房间号。双方准备后，房主发车；赛道、圈数、难度与比赛规则以房主创建房间时的选择为准。每人可选不同的车辆与引擎。两部手机必须访问同一个服务地址。无法连接时检查 Wi-Fi、防火墙及路由器的访客网络／AP 隔离。

## 操作与驾驶反馈

| 动作 | 手机 | 键盘 |
| --- | --- | --- |
| 转向 | 左手横向拖动摇杆，有中心死区与连续转向 | ← / → 或 A / D |
| 油门 | 默认自动；关闭后按住「油门」 | ↑ / W |
| 刹车 | 按住右侧「刹车」，优先于油门和加速 | ↓ / S |
| 漂移 | 方向与「漂移」同时按住 | 空格 + 方向 |
| 加速 | 按住「加速」，消耗氮气储量 | Shift |
| 道具 | 道具模式下点击已拾取的道具 | E |
| 视角 | 点击顶部「跟车 / 引擎盖」 | C |
| 菜单 | 点击右上角暂停 | Esc |

转向响应随车速与抓地负荷变化，高速急弯会降低抓地和速度。坡度、空气阻力、松油门、制动与引擎调校影响纵向加速。自动六挡变速箱带换挡迟滞，电驱采用单挡；仪表显示速度、挡位、转速、制动和抓地状态。车轮随车速转动，前轮随转向偏转，车身有制动俯仰、侧倾和坡度姿态。跟车镜头随速度调整距离与视野，也可切换引擎盖视角。

手机支持多指同时操作；触摸取消、失焦和切换应用会清理输入。单人切到后台会暂停。联机菜单与后台不会暂停其他玩家，当前车辆会刹车；网络输入超过 900 毫秒未更新也会自动刹车。返回前台可从菜单继续。WebGL 上下文丢失时暂停并等待浏览器恢复，恢复后可继续。

音效默认关闭，可在车库或比赛菜单切换，静音选择会保存。声音为转速谐波、风噪、轮胎滑移与碰撞合成音效；燃油引擎的转速回落和电驱声音各有差异。

车辆仍沿闭环赛道前进，玩家控制横向走线与纵向速度；此版本采用适合手机操作的简化驾驶模型，没有独立四轮悬挂、自由探索或倒车。

## 比赛规则

- 每局六车：单人 + 五辆 AI，或双人 + 四辆 AI；可选两圈或三圈。
- 默认「赛道竞速」：保留加速带，不生成道具箱、油污或路障，漂移不发放释放奖励。AI 根据前方弯率选择线路并提前制动。
- 「道具竞速」：补给箱、加速带、油污和路障恢复；加速带按车身与移动轨迹接触判定，擦边即触发、当帧提速，持续 **3.7 秒**，无需按住油门或氮气；主动刹车优先，停留在带上不会反复追加提速；漂移持续超过 0.65 秒后松开可获得氮气和短暂加速。
- 车身与护栏碰撞会损失速度并产生横向推挤；车重影响碰撞分离。长轴距 GT 更耐撞。
- 氮气耗尽后按住不能继续加速；松开后缓慢恢复。制动会压过当前加速效果。
- 根据帧内真实越线时刻计算冲线顺序和单圈时间。第一辆车冲线后最多再等待 35 秒；整场比赛最长 300 秒，未完成标记 DNF。
- 道具箱贴合路面，按完整运动轨迹检测拾取。每车独立判定，拾取后隐藏三秒；满槽不消耗箱体。短按道具通过递增序号同步，避免跨帧或网络采样丢失。
- 超级氮气：三秒加速并补充储量；油污：身后留下持续十八秒的陷阱，减速／打滑 2.4 秒；减速脉冲：影响前方六十五米内未受保护的车辆 3.5 秒；防撞护盾：持续六秒，抵挡速度惩罚，仍保留物理分离。

| 车辆 | 驾驶特点 |
| --- | --- |
| 赤曜 GT | 中置双门跑车，均衡调校 |
| 银箭 R | 开放座舱赛车，轻量、加速和转向更快 |
| 曜夜 GTS | 长轴距 GT，质量更大、耐撞，起步稍慢 |

海岸公路、山岭隘口与都市夜环均保留独立闭环路线，在绕圈中加入 **320 米平直加速区**，沿同一车道布置三个加速带，间隔七十米。出口保留一百二十米直线供驾驶者稳定车辆和准备制动；直线区入口前八十米和出口后一百二十米内不摆道具箱、油污或路障。所有加速带均布置在直线上，之前至少八十米、之后至少一百二十米不摆静态障碍物。剩余补给箱和障碍物布置在其他路段，并保留横向绕行空间。赛道预览与小地图按实际路线边界缩放，金色路段标出连续加速直线。

## 手机自动画质

硬件提示只用于选择启动档位。比赛通过实际渲染间隔和 CPU 绘制时间，持续判断负载；后台时间与首次编译预热不参与判定。持续慢帧会降档，稳定运行后可逐级恢复，设备性能上限防止弱设备反复升档。浏览器没有提供内存／核心数时，从均衡档开始实测。

| 档位 | 渲染目标 | 像素比上限 | 总像素预算 | 实时阴影 / 额外场景细节 |
| --- | --- | --- | --- | --- |
| 流畅 | 30 fps | 0.72 | 65 万 | 关闭 |
| 均衡 | 60 fps | 1.0 | 125 万 | 关闭 |
| 高清 | 60 fps | 1.5 | 240 万 | 开启，1024 阴影 |
| 精细 | 60 fps | 2.0 | 360 万 | 开启，2048 阴影 |

像素比同时受屏幕尺寸、设备 DPR 与总像素预算限制。高档启用车漆涂层；低档保留反射、玻璃、轮胎、路面纹理、静态车底阴影及相同的比赛规则。静态车身按材质合并，护栏立柱与植被使用实例化，粒子复用，远车隐藏，车库限至三十帧。比赛采用固定 60 Hz 物理步长；单人本地运行，联机由服务端计算，画质差异不会改变比赛规则。

这些是渲染目标和资源预算，实际帧率、发热、耗电仍取决于设备、浏览器和后台负载。诊断对象 `window.__racerDebug` 可只读查看当前档位、像素比、帧率、绘制次数及资源数量。

## 验证

```sh
npm run check
npm test
```

可选浏览器审计需要 Playwright、Chrome 和运行中的服务：

```sh
node test/browser-audit.cjs
node test/realism-browser.cjs
node test/boost-pad-browser.cjs
node test/straight-browser.cjs
```

Playwright 不在本目录时，设置 `PLAYWRIGHT_MODULE` 指向包目录。`RACER_URL` 可覆盖测试服务地址，`CHROME_CHANNEL` 可覆盖浏览器通道。覆盖范围和实际结果见 `test/VALIDATION.md`，截图位于 `test/artifacts/`。浏览器设备参数模拟不等同于真实低端／高端手机 GPU 性能测试。
